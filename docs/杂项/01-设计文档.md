# 《暗礁》设计文档 v1.0

> 锈湖式点击解谜 · 反走私题材 · 移动端 H5
> 文档状态：设计已收口，可进入开发
> 最后更新：2026-10-14

---

## 1. 一句话概括

海关缉私新人**林深**在父亲殉职十周年这天，从一只被重新贴过封条的集装箱开始，用 7 件证据拼出一张走私网络与保护伞的网——但网收得多紧，取决于他找到了什么，也取决于他在最后一夜里说对了什么。

## 2. 核心参数

| 项 | 值 |
|---|---|
| 类型 | 锈湖式点击解谜（point-and-click adventure） |
| 平台 | 移动端 H5，**竖屏 9:16**，手机浏览器优先，PC 兼容 |
| 时长 | 10–15 分钟 |
| 画面 | 8 张静态场景 + 标题画 + 结局底图 |
| 技术栈 | Vite 8 + TypeScript 7 + Phaser 4 |
| 交互 | **无对话选项**，全部信息通过点击场景热点获取 |
| 核心机制 | 收集 2 关键道具 + 5 常规线索 → 决定结局大类；第三章对峙表现 → 决定升降级 |
| 结局数 | **6 个** |
| 存档 | localStorage：结局图鉴 + 从头重玩 |

## 3. 世界观与时间线

- **地点**：沧澜港（虚构的南方深水港）
- **时间**：**2026 年 8 月 8 日** —— 父亲林建国殉职十周年当天

| 幕 | 时间 | 场景 |
|---|---|---|
| 第一章 | 黄昏 | 码头集装箱区 |
| 第二章 | 深夜 | 昌隆号油轮 |
| 第三章 | 雨夜 | 废弃仓库 |

### 3.1 「8 月 8 日」的四层含义（核心枢纽）

这一个日期同时是：

1. **海关法治宣传日** —— 海关系统内部人人都记得的日子（现实设定）
2. **父亲林建国的殉职日** —— 十年前的同一天
3. **保险柜密码 0808** —— 李副局长设的，是纪念也是嘲弄
4. **航海日志上那条手写航线的日期** —— 走私团伙**故意选在父亲忌日出货**

> **设计要点**：林深接替父亲驻守沧澜港的**第一天，就是父亲的忌日**。这条线把三章、密码、旧案、六个结局全部串成一根。

## 4. 人物

| 人物 | 身份 | 叙事作用 |
|---|---|---|
| **林深** | 海关缉私局新人警员，第一人称视角，无立绘 | 玩家化身 |
| **林建国** | 林深之父，十年前殉职的缉私警（仅闪回出现） | 情感锚点，旧案线 |
| **老周** | 码头仓库管理员，年长、耳背，**知情线人** | 信息源 / 红鲱鱼 |
| **陈老板** | 走私团伙头目（第三章左侧阴影） | 明面 BOSS |
| **李副局长** | 分管副局长，代号**「信天翁」**（第三章右侧办公室门口，戴口罩） | 保护伞 / 真凶 |

### 4.1 老周的角色设计

- 他是父亲当年的**线人**，一直知道内情但不敢说，用耳背当挡箭牌
- 走私团伙用**薄荷烟**（特供烟）拉拢他，是众多贿赂品之一
- **红鲱鱼**：薄荷烟同时是"码头高层特供"，所以烟蒂出现在他脚边时，玩家会怀疑他才是内鬼——第三章由物证推翻
- 他眼看着林深撬箱、偷货却不阻止——他在**借林深的手翻案**

### 4.2 李副局长的动机

> **第三章要让玩家听见"李副局长"这四个字**：判定表里第三回合的正解靠的是"内鬼代号信天翁 = 李副局长"，但整局游戏在此之前从没在屏幕上出现过这个名字（结局文案里有，那是事后）。所以第三回合的台词直接点了名，答对后再补一句揭晓 —— 玩家不该靠猜。

- 十年前为走私团伙提供通关掩护，被林建国查到，于是灭口
- 取走父亲的半块警号牌作**投名状**交给陈老板，锁进昌隆号保险柜
- **在警号牌背面刻上自己的代号「信天翁」** —— 把它当战利品收藏，病态炫耀，笃定死人不会说话
- **正是因为这份傲慢，它最后成了定他罪的铁证**（此动机由第三章他自己说破）

## 5. 道具与线索总表

### 5.1 关键道具（2 件，证明的是「十年前」）

| 道具 | 获取位置 | 作用 | 隐喻 |
|---|---|---|---|
| **蛇形铜徽** | 第一章·集装箱内壁夹层最深处的手抠暗格 | 走私集团核心信物，证明本案与父亲旧案同源 | 团伙发的信物，父亲卧底时被迫持有——既是护身符也是枷锁 |
| **半块警号牌** | 第二章·昌隆号船长室保险柜（密码 0808） | 背面刻有内鬼代号「信天翁」，坐实保护伞身份 | 父亲殉职时摔裂的遗物，一半在儿子手里，一半在凶手手里 |

**暗格的来历**：夹层是团伙用专业工具改装的（= 线索 1），而暗格是父亲在夹层深处**用指甲抠出来的**一道歪斜的缝，边缘粗糙。**专业切割 vs 手抠痕迹的视觉对比**，直接在画面上告诉玩家"这是两个人留下的"，也解释了为什么十年没人发现。

### 5.2 常规线索（5 条，证明的是「眼前这批货」）

| # | 线索 | 位置 | 证明什么 |
|---|---|---|---|
| 1 | **夹层切割痕迹** | 第一章·集装箱内壁 | 内壁被专业工具切割出夹层——**内部人员改装** |
| 2 | **薄荷烟蒂** | 第一章·集装箱外右侧死角（老周脚边） | 团伙特供烟，**码头内部已被渗透**（红鲱鱼：疑似指向老周） |
| 3 | **涂改提货单** | 第一章·集装箱内木箱缝隙 | 报关单被篡改，落款有蛇形暗记——**货物造假** |
| 4 | **油轮航海日志** | 第二章·办公桌抽屉 | 多笔未报备的夜间航线，对应走私接驳点 |
| 5 | **保护伞名单残页** | 第二章·保险柜 | 海关内部人员的代号与受贿记录 |

> **设计洞察（判定表的底层逻辑）**：关键道具证明**过去**，常规线索证明**现在**。所以即使手握铜徽与警号牌，只要线索 ≤2 条，你连仓库里有什么都说不清，行动照样扑空。

### 5.3 工具与附属道具

| 道具 | 位置 | 用途 |
|---|---|---|
| **海关封条** | 第一章·集装箱门锁（撕下） | 第三章**可出示**（打中第三回合，给的是气势，不改结局判定） |
| **撬棍** | 第一章·左侧积水地面角落 | 撬通风口 → 撬木箱堆 → 撬开暗格 |
| **象牙样本** | 第一章·夹层暗格（与铜徽同处） | 第三章**可出示**（打中"保护伞"回合，不改结局判定） |
| **底舱钥匙** | 第二章·走廊消防栓玻璃内 | 开底舱门 |

> 撬棍与底舱钥匙在第三章**灰显不可选**（"这玩意儿对峙时没用"）。
>
> **封条与象牙曾经是"文档里可出示、代码里打不中"**：`items.ts` 里这两件的 `tags` 是空数组，而判定只认 tags（`EndingResolver.ts` 的 `holdsAnswerFor`），所以点了等于白点、还照记一次破绽。现已补成 `['protection']` —— 它们打中的是第三回合，而第三回合的正解仍是半块警号牌，所以**出示它们不改变任何结局**，只是不再无辜挨罚。
>
> ⚠️ 改动这两件时必须同时看 `tests/EndingResolver.test.ts:258`：「持有正确牌却出错了 → 破绽」用的正是**保护伞名单残页**，所以残页的 tags 必须保持为空 —— 它证明的是"海关内部有人"，证不出"内鬼就是李副局长"，这是刻意的红鲱鱼。

## 6. 章节流程

### 6.1 第一章：异常集装箱

**场景 1 · 黄昏码头（集装箱外景）**

| 热点 | 交互 |
|---|---|
| 集装箱门锁 | 撕下「**海关封条**」→ 文字："封条完好，但胶痕是重新压过的——内部开箱后重新贴上的" |
| 左侧积水地面角落 | 获得「**撬棍**」 |
| 通风口 | **需撬棍** → 撬开 → 进入场景 2 |
| 右侧地面死角（老周脚边） | 获得线索 2「**薄荷烟蒂**」 |
| 仓库管理员老周 | 固定对话："夜里常有油轮不靠岸，在锚地飘着" → 尝试推进章节 |
| （出口）通风口 | 往返场景 1 / 2 |

**场景 2 · 集装箱内部**

| 热点 | 交互 |
|---|---|
| 木箱堆 | **需撬棍** → 撬开 → 大量碎象牙 → 木箱缝隙中获得线索 3「**涂改提货单**」 |
| 内壁壁板 | 发现线索 1「**夹层切割痕迹**」 |
| 夹层暗格 | **需撬棍 + 已发现切割痕迹** → 撬开 → 获得「**蛇形铜徽**」+「**象牙样本**」→ **触发闪回 1** |
| 通风口 | 返回场景 1 |

**章节推进**：点击老周 → 若有遗漏，弹「要不要再找找？」→ 再次点击老周 → 进入第二章

### 6.4 破绽系统（对峙表现）

> **破绽满 3 的收束段**：`FUMBLE_OVERFLOW_TEXT`（戴口罩的人「行了。」／他转身走进办公室／我站在原地）原来写了但没人播 —— `applyFumbles()` 在 `fumbleCount >= MAX_FUMBLES` 时直接返回 `tipped_off`，正文里却没有任何一句交代"为什么突然就到这一步"。现在 `composeParagraphs()` 在满 3 时把它接在正文后面（1~2 次破绽走的是 `FUMBLE_PARAGRAPHS`，本来就是接上的）。
>
> **写这段时注意**：不能写成 `**戴口罩的人**：` 那种标记 —— 全仓没有 markdown 解析器，星号会原样显示在结局页上。

**核心原则：收集决定「你有什么牌」，顺序决定「你打得好不好」。**

| 情况 | 判定 |
|---|---|
| **持有**正确牌，却出示了别的 | **破绽 +1**，给出压制性反馈，**可立即重试** |
| **没有**正确牌 | **不计破绽**，剧情自然推进（这已由基础判定表惩罚过，不重复扣） |
| 每回合上限 | 最多记 1 个破绽（反复出错不叠加） |
| 总上限 | 3 个 |

**降级链**

| 破绽 | 结果 |
|---|---|
| 0 | 基础结局（完整版文案） |
| 1–2 | 降一级（见下表） |
| 3 | 无条件进入「**打草惊蛇**」 |

**降级映射**

| 基础结局 | 层级 | 降 1 级后 |
|---|---|---|
| 潮落 | L1 | 残页（**失误版**文案） |
| 残页 | L2 | 无证之胜（**失误版**文案） |
| 遗徽 / 断号 | L3 | 无证之胜 |
| 无证之胜 | L4 | 打草惊蛇 |
| 打草惊蛇 | L5 | 打草惊蛇 |

> **为什么残页降级跳过 L3**：L3 的两个结局（遗徽 / 断号）定义就是"缺一个关键道具"，把两个道具都在手里的玩家塞进去会自相矛盾。而 L4「无证之胜」的核心是"下层全抓、顶层漏网"，与"物证齐全但临场失手"兼容。

**破绽的可见性**：不显示数字。每次出错有明确音效 + 一句压制性文字反馈，结局时体现。

### 7.2 六个结局

| # | 结局 | 触发 | 基调 |
|---|---|---|---|
| 1 | **潮落** | 2 道具 + 5 线索 + 0 破绽 | 完美 |
| 2 | **残页** | 2 道具 + 3~4 线索（0 破绽） | 准完美 |
| 3 | **遗徽** | 缺铜徽 + ≥3 线索 | 悬案未结 |
| 4 | **断号** | 缺警号牌 + ≥3 线索 | 凶手逍遥 |
| 5 | **无证之胜** | 0 道具 + ≥3 线索 | 惨胜 |
| 6 | **打草惊蛇** | 线索 ≤2（或破绽满 3） | 失败 |

### 7.3 残页结局的「细节变量」

按缺失的线索生成对应句子，**最多并列 2 条**：

| 缺什么 | 对应句子 |
|---|---|
| 缺「保护伞名单残页」 | 最顶层的联络人永远隐在了墨团里 |
| 缺「航海日志」 | 仍有秘密走私航线未被摸清 |
| 缺「薄荷烟蒂」 | 无法锁定管理层参与的实据 |
| 缺「涂改提货单」 | 货物来源链条缺了关键一环 |
| 缺「夹层切割痕迹」 | 无法证明集装箱是内部人员改装 |

「无证之胜」的文案同样**随线索数（3 / 4 / 5）变化**。

## 9. UI / UX

### 9.1 主界面

- **场景视图**：全屏静态画面
- **底部道具栏**：横向可滚动，道具图标 + 名称；已获得的线索以条目形式并列
- **道具栏排序：按获得先后追加，已有格子的位置永不改变。**
  实现时曾按「关键道具 → 线索 → 工具 → 物证」分组排列，结果是每捡到一件东西
  整条栏都会平移 —— 玩家手指正点在「撬棍」上，它却在这一瞬间挪到了隔壁，
  选中的变成别的东西，接着对着木箱堆点半天毫无反应（真人玩会当成 bug）。
  按类别分组好看，但对「先选道具、再点热点」的交互是危险的，故放弃。
- **热点**：无高亮提示（锈湖式），鼠标/手指悬停时轻微光标变化
- **点击反馈**：点中热点时在落点弹一个 300ms 的琥珀色扩散环（C3）。
  设计稿写的是「轻微缩放」，实际改成落点扩散环 —— 场景美术是整张静态图，
  没有可缩放的物件；环画在落点，反馈的是「这一下收到了」而不是「这个东西动了」。
  同时播放 `hotspot` 音效。环只活 300ms，所以另给开发钩子一个计数器
  （`__anJiao.ripples()`）供烟测断言，截图抓不稳它。
- **点空白处 = 放下手里的道具**（取消选中）
- **用错道具**：给一句「「X」用在这上面不对。」并取消选中，不消耗道具
- **右上角返回按钮**（C2）：常驻，返回标题页。**点第一下变成「再点一下回标题」**
  并进入 2.6 秒待确认态，2.6 秒内再点才真的回去 —— 手机上误触的代价是整局重来。
  待确认期间按钮变宽、文字变亮，状态可见。有浮层打开时按钮让位（浮层优先）。
- **道具栏左上角「证据」按钮**（C1）：见 9.6。手持道具时那一行显示「手持：××」，
  此刻它不是按钮（避免"明明按在道具上却弹出证据列表"）。

- **单页滚动**，不做左右翻页

### 9.3 「要不要再找找？」

- **触发点**：第一章点老周时 / 第二章点底舱门锁时
- **条件**：仅当存在未发现的线索或道具
- **行为**：弹出提示 → **3~5 秒后自动消失** → 玩家**再次点击同一热点**才推进章节（不设时限）
- 若已全收集 → 直接推进

### 9.4 闪回

- 拿到铜徽 → 闪回 1（0.5 秒，黑白，父亲的手握着同一枚铜徽）
- 拿到警号牌 → 闪回 2（黑白，父亲倒地，警号牌摔成两半，远处皮鞋脚步声）
- 无台词，纯视觉，不可跳过（时长本身极短）

### 9.5 结局图鉴

- 主菜单入口，6 格
- 每格上半是**这张结局插画的缩略图**（278×113，直接调 `paintEndingPlate` 画小一号），
  下半是结局名 + 一句摘要
- 未解锁：缩略图上面压一层 `0x0b1116`、alpha 0.78 的暗幕 —— 看得到"是什么形状"，
  看不到细节；标题位沿用 `？？？`，摘要照常显示
- 解锁后可从主菜单「重新开始」

**为什么锁定卡也要画缩略图**：原来锁定状态是一张空卡 + `？？？`，六格长得一模一样，
玩家看不出还差什么、也得不到"再打一次"的钩子。剪影只给形状不给细节，
既留了悬念又让六格互不相同 —— 而这张缩略图是**复用**正文那张插画的绘制函数，
不是另画一套，所以永远不会和正文对不上。

**摘要最长 33 字，必须能放进两行**：卡片宽 280、摘要区宽 244、字号 14px，
33 字正好两行；用 `src/ui/cjkWrap.ts` 做中文避头尾折行，所以不会出现
「，」或「。」独占一行。**这个上限是排版算出来的，改摘要文案前先数一遍字数。**

### 9.6 证据列表（C1）

**为什么需要它**：11 件道具里有 4 件是文档 —— 涂改提货单、油轮航海日志、
保护名单残页、半块警号牌背面。玩家读过一次，那张纸就再也调不出来；而第三章
对峙恰恰要求引用纸上的内容，道具栏却只给 6 个字的道具名。玩家只能凭记忆选牌，
选错还要吃一个破绽 —— 这不是难度，是记忆惩罚。

- **入口**：道具栏左上角的「证据」标签（本来就空着的那块）。不另起按钮 ——
  道具栏已经没有多余高度了（底部安全区刚够 30px）。
- **内容**：已获得的全部证据，按获得顺序（与道具栏同序）。每行是
  程序化图标 + 名称 + 类别（关键道具 / 线索 / 工具 / 物证）+ 一句话描述。
  带原件的 4 件右侧多一句「重读原件 ›」（琥珀色），点它复用 9.2 的纸面浮层。
  没有原件的行不给可点提示 —— 做成"看起来能点"反而是骗人。
- **不做分页、不做滚动**：最多 11 件，一屏放得下。真放不下再说。
- **关闭**：面板右上角 ✕，或者点面板外任意处。**关闭逻辑挂在全屏背板上，
  不靠场景转发点击坐标** —— 打开列表的那一下点击本身落在道具栏上（y≈1120），
  也就是"面板外"，转发坐标的写法会让同一下点击把它立刻关掉。
  背板随容器一起变可见，而这一下点击的命中列表在它变可见之前就已经算完了。

### 9.7 横屏提示（C7）

游戏是 720×1280 的竖屏舞台，`Scale.FIT` 遇到横屏会把它压成中间很窄的一条。
`index.html` 里加一层全屏提示让玩家把手机转回来，比让他自己琢磨
"为什么这么小"要好。

- 媒体查询用 `(orientation: landscape) and (max-height: 560px)`，
  **不是只按 orientation**：桌面浏览器窗口几乎都是横的（1440×900 很常见），
  只按 orientation 挡会把桌面用户一起挡住。
- 提示层挡输入（`z-index: 10`、不设 `pointer-events: none`）—— 横屏下这个
  布局就是不可玩的，与其让玩家在一条窄缝里点错，不如让他先转回来。

> **实现说明**：图鉴摘要也用 `src/ui/cjkWrap.ts` 的中文避头尾折行，
> 所以卡片里不会出现「，」或「。」独占一行。未解锁格子的 `？？？`
> 是三个问号本身，不是被折断的标点 —— 用脚本断言「没有标点孤行」时要把它排除掉。

### 9.8 标题页与制作信息

标题页：大标题「暗 礁」+ 副题「2 0 2 6 · 沧 澜 港」+ 三个等高等距的按钮
（开始调查 / 结局图鉴 / 判定表 · 调试面板，层级靠字号与文字色表达，几何一律统一）
+ 底部一行归属说明。

**背景不能只是一张渐变**。原来上半屏是一块近乎纯黑的渐变、下半屏一片水色，
中间连一条地平线都读不出来 —— 玩家第一眼看到的是"还没做完"。现在从天到水
依次是：月亮（同心圆叠出的光晕 + 一颗 5px 的亮芯）→ 港区剪影（两台龙门吊、
三座仓库，吊臂端点各有一点琥珀色灯）→ 地平线（y=620）→ 水面（月亮的倒影
是一叠横向短条）→ 退潮后的礁石（压在 -2 层）+ 沉在水里的铜徽。

**渐变必须给足段数**。天空最早只分了 7 段，每段 88px、相邻色差又大，
屏幕上是七条硬边横带 —— 一眼看成渲染坏了。夜里那段色域本来就窄，
靠"少画几段"省不下来什么：`verticalGradient()` 按每段 5px 算段数
（`Math.max(24, round(h/5))`），两色之间线性插值。

**雨在标题页是通铺的**（y 0~880，150 根），而且比场景里的更粗更斜 ——
标题页没有"车里""舱内"这种遮挡关系，不用像场景那样给它划边界。
再叠一层 16 条水面反光的 `addShimmer`，标题页的水就一直在动。

**底部说明文字是「‘钱江杯’大学生反走私创作比赛作品」**，不是玩法描述 ——
这一行承担的是参赛作品的署名，玩家点进来第一眼要看到它。
弯单引号 `‘’` 要写对：衬线/无衬线字体下 ASCII 直引号的方向是反的。

**左下角那枚沉在水里的铜徽（`src/ui/CreditsPanel.ts`）是标题页唯一的隐藏入口**，
点它弹出制作信息面板：

- 七行「标签 / 值」（制作人 / 音效 / 剧本 / 美术 / 程序 / 指导老师 / 特别鸣谢），
  没填真名的先留 `AAAAA`。真值只在 `CreditsPanel` 顶部的 `ROWS` 表里替换，版面不动。
- 底部单独一句 **「本游戏由AI辅助制作」**（`CreditsPanel` 顶部的 `NOTE`）。
  它**不进 `ROWS`** —— 那不是「标签 / 值」的关系，是一句整话，挤进两列表格里
  会既不像标签也不像值。颜色用 `inkDim`，比它下面的「点击面板外关闭」亮一档：
  前者是内容，后者是操作提示。
- **面板高度 600 是按内容量出来的**：七行到 y846，AI 声明在 y890
  （`PANEL_H - 82`），关闭提示在 y940（`PANEL_H - 32`）。面板只往下长，
  顶边 372 不能动；**再加行必须同时把 `PANEL_H` 加大**，否则会和底部撞上。
- **命中区半径 46，图形只有 30**：手机上 60px 的靶子折合只有约 32 个 CSS 像素，
  手指点不准。多出来的 16px 是看不见的，不参与构图。
- 铜徽外面套一圈很淡的呼吸光（alpha 0.16 ↔ 0.46，1700ms），
  暗示"这个能点" —— 手机上没有任何悬停反馈，没有它就等于没有入口。
- 关闭有两条路：**点面板外**（全屏背板）和**右上角 ✕**。
- **关闭逻辑必须挂在背板自己身上**，不能让场景层转发坐标：打开浮层的
  同一下点击就落在面板外，会被自己当场关掉（C1 证据列表踩过同一个坑）。
  背板随容器一起由 `setVisible(false)` 变可见，而这一次点击的命中列表
  在它变可见之前就算完了，所以它只会接住下一根手指。
- 面板顶边定在 y=372：标题「暗 礁」是 96px 字号、中心 y=300、墨迹压到约 350，
  从 340 起会把标题下半截切掉，看着像没画完。

### 9.9 章节卡（`src/ui/ChapterCard.ts`）

进每一章之前的一张过场卡，1.7 秒，点一下跳过。

**旧版是全屏纯黑 + 一个标题**，三章除了字以外完全一样 —— 玩家分不出这是第几章，
也感觉不到"换了个地方"。现在每张卡由这些东西组成：

- 一块 500×320 的底板，`0x05080b` 压一层该章的 `frameTint`（alpha 0.16），

- 「第 一 章」，20px、字距 10
- 一道 56×2 的琥珀色短横，`scaleX` 从 0 拉到 1（520ms）—— 这是一整张卡里唯一的动
- 章节名 46px
- 一条 220px 的细线，然后时间、地点提示
- 右下角是**该章序号的巨大水印**（176px、`#0f171e`），压在章节名底下
- 四角各一组 L 形角标

**底板颜色不跟章节无关地乱选**：`frameTint` 就是结局插画用的那个色，
一章从过场卡到结局屏是同一个色系。

### 9.10 调试面板的开关（`src/debugPanel.ts`）

标题页第三格「判定表 · 调试面板」通向 `src/scenes/DebugScene.ts`。
**这一格在不在，由 `src/debugPanel.ts` 里的一行决定：**

```ts
export const DEBUG_PANEL = 'open' as 'open' | 'closed';   // ← 改这一个字符串
```

- `'open'`：标题页三格齐全，`DebugScene` 注册进 Phaser。
- `'closed'`：标题页**不画这一格**，`DebugScene` **也不注册**
  —— 关卡里没有任何路径能进到它，`?dev=1` 也调不出来。

几条不能改的约定：

- **这是编译期常量，不是运行时开关。** 改完必须重新 `npm run build`
  （或让 dev server 重新编译）才会进产物。这是故意的：交件前想知道
  "评委看到的是不是干净的"，就把这行改成 `'closed'` 重新构建一次，
  而不是靠记性去点。
- **关掉时只少画那一格，前两格一个像素都不动。** 开关不允许改变正式界面的
  版面 —— 否则"关掉调试面板"会顺带挪动「开始调查」和「结局图鉴」，
  那就不再是同一个版面了。（实测：两版各截一张标题页，裁出的
  「开始调查 / 结局图鉴」两格逐像素一致。）
- **末尾的 `as 'open' | 'closed'` 不能省。** 只写
  `export const DEBUG_PANEL: 'open' | 'closed' = 'closed';` 的话，
  TypeScript 的控制流分析会把它的实际类型收窄成字面量 `'closed'`，
  下面那句 `DEBUG_PANEL === 'open'` 直接报 TS2367
  「没有重叠，这个比较多半是写错了」—— 开关一旦真的改成 `'closed'`
  就编译不过。断言成联合类型之后初始化表达式的类型本身就是联合，
  收窄无从下手。
- **关掉不会让 DebugScene 从 bundle 里消失。** Phaser 的 Scene 是带副作用的类，
  不能指望 Rollup 因为"数组里没有它"就把它抖干净（实测只少约 2.4 kB）。
  关掉的收益是"进不去"，不是"那几 KB"。

两条烟测路线各测一个状态（`tools/regress.mjs` 不跑它们，改开关时手动跑）：

| 路线 | 断言 |
| --- | --- |
| `tools/steps/_debug-open.json` | `titleButton('判定表 · 调试面板') !== null`；点进去 `active()` 里有 `Debug` |
| `tools/steps/_debug-closed.json` | `titleButton(...) === null`；且 `screen('Debug')` **必须抛异常**（`dev.ts` 的 `screen` 查不到 key 就 throw，正好证明场景真没注册） |

⚠️ 断言"点进去到没到 Debug"要用 `__anJiao.active()`，**不能用 `__anJiao.scene()`**
—— 后者是 `explore()?.devScene?.() ?? ''`，只读 Explore 场景，在 Debug 里恒为空串。

### 9.11 续玩与音效开关

#### 续玩（「继续调查」／「重新开始」）

原来存档只干一件事：解锁结局。`SaveManager` 的 `saveProgress()` / `clearProgress()` 写好了但**全仓没有调用方**，`GameState.snapshot()` / `restore()` 也一直是完整的 —— 能力全在，只是没人接。后果是在手机上切个后台、标签页被系统回收，四十多分钟整局白玩。

现在接上了：

| 环节 | 落点 |
|---|---|
| 存档形状 | `Progress = { sceneId, snapshot }`；`SaveData.version` 仍是 1，新增可选字段 `progress` |
| 写档时机 | `ExploreScene.create()` 里 `markVisited()` 之后；以及 `run()` 的 `finally`（每次交互结算完） |
| 读档 | 标题页读 `load().progress`：有档 → 主按钮变「继续调查」，下面多一条「重新开始」 |
| 清档 | `EndingScene` 出结局时 `unlockEnding(id)` 顺手清掉 progress（一局结束）；「重新开始」也是清档后重进 |

六条约束：

1. **`progress` 必须是 `{sceneId, snapshot}`，不能是裸的 snapshot**。老档里它是 `null`，但万一有人手改 localStorage 塞了个裸 snapshot 进来，`restore()` 会把它当空档读、把玩家丢回第一章。`isProgress()` 会拒掉形状不对的，退回 null = 「没有可续的档」。
   **而且它必须把 `snapshot` 里四个数组和两个计数逐个验一遍**，只验「是个非空对象」不够 ——
   见下面第 5 条。
2. **续玩时对上一次停留的场景要 `forgetVisited(sceneId)`**。`warehouse_night` 的 `onEnter` 是 `say` + `confrontation` 两段，而 `firstVisit` 挡着第二次进不再播 —— 续玩正是"第二次进"。不忘记它，玩家会落进一个没有引子、直接弹对峙的仓库。
3. **`clearProgress()` 只清进度、不动 `unlockedEndings`**。图鉴是跨局的收藏，一起清就是把玩家攒的六个结局抹了。
4. **「重新开始」要点两下**。它是唯一会把当前进度清零的按钮，偏偏就贴在主按钮下面，一下误触就是四十多分钟。第一下只把标签换成「再点一次，确认重来」并换成警示色，第二下才真的清 —— `restartArmed` 存这个状态。

5. **存档边界要把快照验到底，事件处理器里绝不抛异常。** `restore()` 是在「继续调查」的 `pointerdown` 回调里跑的，那里抛出来的异常会被 Phaser 的输入循环吞掉 —— 页面不白屏、不重启，控制台只有一行 `TypeError`，玩家看到的就是**一个点了没反应的按钮**。所以两道防线都要有：
   - `isProgress()` 逐个验 `snapshot` 的四个数组（`items` / `flags` / `visited` / `fumbledRounds`）与两个计数（`fumbleCount` / `roundIndex`）。光验「`snapshot` 是个非空对象」会让一个 `snapshot: {}` 的档一路走到 `for (const id of snap.items)` 才炸。
   - `restore()` 自己再对每个字段给默认值（`?? []` / `?? 0`）—— 它还会被 dev 钩子和单测直接调，不能指望调用方都干净。

   这个 bug 是拿 `tools/steps/_stress.json` 真塞了一个畸形档复现出来的，现在那条例外路线已经挂进回归矩阵（见 §11.6 的 `bad-save`）。

6. **`sceneId` 必须指向一个真实存在的场景。** 形状对了、`snapshot` 也验干净了，仍然可能是一个"说不通"的档：
   `ExploreScene.init()` 是 `SCENES[data.sceneId ?? fallback] ?? SCENES[fallback]!` —— 认不出的 id 会**静默回退到第一章**，
   而 `restore()` 已经把道具和 flag 全灌进去了。实测塞 `sceneId: 'no_such_scene'`：标题页照给「继续调查」，
   点下去玩家带着 `bronze_emblem`、`crates_opened` 站在码头，而第一章用过的地方全是死的（flag 已还原）。
   不崩、不报错，只是把一个自相矛盾的状态摆给玩家看。
   所以标题页除了看 `progress` 在不在，还要确认 `SCENES[raw.sceneId]` 存在；不存在就 `clearProgress()`、退回「开始调查」。
   触发条件很现实：以后改场景 id、删场景，旧档就会走到这条路。

#### 音效开关

`Sfx.isMuted()` / `setMuted()` 一直是完整的：状态有、`MUTE_KEY` 持久化有、`playSfx()` 开头那道 `if (muted) return` 也在 —— 差的是一个调用方。所以补的是 UI，不是那两个函数。

- 位置：标题页右上角 `(GAME_WIDTH - 64, 64)`。开 = 浅蓝喇叭 + 两道声波，关 = 灰喇叭 + 一道橙斜杠（比"整体变灰"更容易一眼分辨）。

这不是占位，是这套美术的方向 —— 雨夜暗场里，一张没有脸的白头比任何
五官细节都更快被读成"这里站着一个人"。三个人共用同一个肤色

三条实现时的硬约束：

1. **图形必须落在命中区里**。老周 `[572,772,148,236]`（`chapters.ts` 的
   `zhou`）· 陈老板 `[40,418,140,382]` · 李副局长 `[512,288,178,502]`
   （后两个在 `data/confrontation.ts` 的 `CONFRONTATION_TARGETS`，
   有单测钉死三者互不重叠）。帽顶到鞋底整个身形都得在该矩形内。
2. **李副局长的口罩要留**。概念图上没有口罩，但剧本从头到尾叫他
   「戴口罩的人」，口罩还是全屏最亮的一点。概念图给的是这个人的身份，
   口罩给的是这一场戏的信息 —— 制服说明他是谁，口罩说明他现在不想让人认出来。
3. **比例照概念图量出来的数字画，不要"看着差不多"**。三个人都踩过这个坑：

   | 人物 | 概念图外框（高:宽） | 第一版画成 | 现在 | 踩过的坑 |
   |---|---|---|---|---|
   | 老周 | **3.40 : 1** | 1.67 : 1 | 2.31 : 1 | 画成矮墩墩的方块人 |
   | 陈老板 | **1.74 : 1** | 2.61 : 1 | 2.25 : 1（有意偏离，见下） | 先画高了；压矮之后头 108 / 肚子 132（1.22 倍）又成了雪人 |
   | 李副局长 | **3.00 : 1** | 2.86 : 1 | 2.86 : 1 | 一次就对 |

   **陈老板是唯一一个有意不照概念图比例画的**：1.74 是"单人立绘"的比例，
   按它画出来只有 244px 高，而对峙场对面的李副局长有 400px —— 同框时
   像一个人蹲着，不像两个对手。甲把两个人的高度差压进 2 倍以内之后，
   他停在 295px（2.25 : 1）：仍然明显比对面矮胖，但站得住。
   改的是纵向分配 —— 帽顶从 553 提到 505、肚子拉长、腿保持短，脚不动。

   量法：把概念图的非背景像素取 bbox 得到外框，再按 1/8 高度切横剖面
   看宽度分布（老周在 2/8 处只有 0.38 宽 = 那是脑袋，帽檐 0.85、
   胯部 0.87；陈老板最宽处在肚子的 0.94~0.97）。

   （`shots/chars/compare.png`：左列概念图、右列游戏内渲染）。

   两个人都是在**保持身形特征**（瘦高 / 矮圆）的前提下往可读性折中，

> 暗场差距过大，只能照着形体在 `placeholders.ts` 里重画。

### 10.7 环境动效层（第 2 组 B1 / B2）

场景美术是**一张画死在 `create()` 里的静态图**：`placeholders.ts` 把整个场景一次性
画进一个 `Graphics`，之后再也不动它。于是雨是画上去的斜线、灯是画上去的圆斑、
水面是画上去的横条 —— 整个游戏除了 UI 全是静物。

动效层解决这件事，但**不能靠"每帧重画整张图"** —— 那等于把 900 多条图元每秒重建 60 次。
规矩是：**图形只在建层时画一次，之后只动 transform / alpha**。

| 原语 | 做什么 | 怎么循环 |
|---|---|---|
| `addRain` | 雨 | `TileSprite` 的 `tilePositionY` 从 0 匀速走到 h |
| `addLamps` | 灯光呼吸 / 接触不良的抖 | alpha 0.6↔1 的 yoyo；抖的那盏走固定序列 |
| `addShimmer` | 水面反光 | 分三层错相呼吸（2100/3000/3900ms）+ 极慢左右漂（5200/6900/8600ms） |
| `addMotes` | 光柱里的尘埃 | 两个互质长周期分别驱动 x（7300ms）和 y（5100ms） |
| `addMist` | 贴地/贴海的雾 | 大而极淡的同心圆，9s 呼吸 + 17s 漂移 |
| `addSmoke` | 烟头上那缕烟 | 5 个越往上越大越淡的圆，上下**荡**而不是匀速升 |

`sceneAmbient.ts` 是一张「场景 → 挂哪几层」的表，坐标全部照着静态图抄
（要知道水在哪、灯在哪，才能把反光和水光放对地方）。**改静态图的构图时，
这张表里的坐标要一起改** —— 它不在同一个文件里，编译器不会提醒。

几条踩出来的规矩：

- **雨只下在"本来就该是雨"的地方。** `Graphics` 不裁剪，"整体位移一个周期"
  会把内容推下去整整一个周期 —— 仓库外那场雨雨区写的 0~600，雨丝实际一路画到
  y≈1260，盖到了车内的仪表台和 HUD 上。改用 `TileSprite` 是因为它**自带裁剪**，
  而且就一个 quad，比每帧重建几百条线段便宜。几何遮罩走不通：`createGeometryMask()`
  在 WebGL 下没有实现，Phaser 4 会直接报 *"This method is not supported in WebGL.
  Create a Mask filter instead."*；而 Mask filter 是"跟着被过滤对象一起动"的，
  跟这里要的"钉死在屏幕上的雨区"正好相反。
- **同一个属性不能挂两个 tween**，后一个会覆盖前一个。尘埃的 x 和 y 必须分开挂，
  否则画面变成只在一个方向上来回蹭。
- **抖动不要用 `Math.random()`**：换成固定序列，同一盏灯每次进来抖得一样，
  截图对比时才不会每张都不一样（`addLamps` 的 `flicker`）。
- **和静态图重复的那一笔要删掉**：走廊的三盏灯原来在底图里画了 `glow()`，
  动效层再叠一层就是双份亮度；仓库外那 170 根静态雨线同理。**加一层动效 =
  去底图里删掉对应的那一笔**，不能两套并存。
- **人物单独成层**（`FIGURE_DEPTH = 10 < AMBIENT_DEPTH = 20`），
  这样待机呼吸才能只缩放人、不缩放他脚下的湿地反光。缩放的**原点在脚底**：
  `Graphics` 没有 origin，得把人物画进一个 `y = -footY` 的容器、再把容器摆在
  `(0, footY)` 上，缩放容器时脚不动、只有上半身起伏（`k = 1.012`）。
  三个人用三个不同的周期（3400 / 3600 / 2950ms），同框才不会像一起做操。

**动效层不影响回归**：`settle` 步问的是 `__anJiao.idle()`（busy / textBox / card /
doc / evidence / backArmed 六个游戏状态位），**不看 tween** ——
无限循环的动效 tween 不会把烟测卡死。

### 11.2 关键设计约束

- **GameState 纯数据、可序列化** —— 剧情逻辑与渲染分离，便于测试与重玩
- **判定逻辑集中**在 `EndingResolver.ts`，输入 `(道具集合, 破绽数)`，输出结局 ID —— 可脱离 Phaser 单测
- **剧情数据驱动**：`data/chapters.ts` 用 `SceneDef / Hotspot / HotspotBranch / Effect` 描述
  每个场景的热点、显示条件、解锁条件、结果；`core/Story.ts` 只放类型与纯函数，
  **不 import Phaser 的值**（否则 node 里跑单测会 `ReferenceError: window is not defined`）
- **分支互斥全靠 GameState 判定**（`has(item)` / `hasFlag(flag)`），不额外记「点过几次」——
  存档、重玩、单测都不需要多一份状态
- **渲染与数据靠 `paintKey` 字符串连接**，`SceneDef` 里不出现函数引用
- **竖屏基准分辨率**：`720 × 1280`，`Scale.FIT` 适配；场景区高 1104，道具栏高 176
- **占位美术**：第一阶段用色块 + 标签跑通全流程，剧情与判定稳定后再替换正式美术
- **输入闸门只认「现在能不能操作」，不认「整场还在进行」** —— 拿一个从流程开头
  一直挂到结尾的 `busy` 当闸门，玩家在「轮到你出牌」的整个窗口里怎么点都会被静默
  吞掉（P3 对峙与 P1 对话框各踩过一次这个形状的坑）
- **同一个 tick 里不要对同一个 scene key 先 `stop()` 再 `start()`** —— Phaser 的场景
  队列会把它落成「停掉就不再起来」，`active()` 直接变空。要重开就只调 `start()`
- **夜景要暗，但「要点谁」必须一眼可辨** —— 仓库那场三个目标原本与后墙同亮度，
  玩家看不出左边站着人，只会以为那是墙上的污渍
- **`#game` 容器不要再写 flex 居中** —— Phaser 的 `autoCenter: CENTER_BOTH` 已经会给
  画布加 margin 把它摆正，再加 flex 就是居中两次。在 720×1280 的窗口里画布正好铺满、
  完全看不出来，一换到手机尺寸就被多推约 38px，上下留白不对称（P5 实测抓到的）
- **给脚本点的坐标必须由页面报出来，且是页面坐标** —— 见 §11.5 第二条
- **暗场里「可点」必须看得见** —— 设计上不给热点加高亮（保持画面干净），所以
  形体与光影就是玩家唯一的路标：每个可点物体与**紧邻**背景的明度差至少 2.5:1，
  而且要有自解释的形体（门要有门框、门芯和把手；柜子要有门缝和投影），
  不能拿一根 3px 边线代表一整扇门。整改前的实测值：船长室舱门对舱壁 1.11:1、
  走廊储物柜 1.05:1、走廊左门 1.15:1、集装箱铰链 1.27:1 —— 这些等于不存在。
  同理，一个玩家必须自己发现的热点，图形不该比它自己的命中区小太多
  （老周脚边的烟蒂原来只画了 18×5px）
- **「比背景亮一点点」等于没改，一次抬到位** —— 船长室舱门从 `0x1a2831` 抬到
  `0x1c2a33`、走廊正面铁门抬到 `0x232f38`，两次小步走完实测只有 1.01~1.08:1，
  玩家眼里那还是一块墙。同一扇门一次给到 `0x4d646c` / `0x475d66`，
  门板对紧邻墙才落到 **1.69~1.83:1**（配 2px 门框 + 门芯落差 + 看得见的把手）。
  暗场调色不要试探性小步走，量一次、到位一次
- **暗场里不要靠「面」的亮度去分人与物** —— 对峙场左侧的人与中间货箱的面均亮度
  只差 **1.35:1**，可把箱子提亮到 2:1 会变成一只发光的箱子，比人还抢眼。
  最后改的是**边缘光**：沿防雨布两条斜边各压一道冷高光（`0x9fb4c2`，局部 ≥3:1），
  面均只升到 1.71:1，箱子却立刻有了自己的轮廓
- **同一类东西要一起改，不能只改最显眼的那个** —— 对峙场三个可点目标里先只改了
  「物件」和一个人，另一个还是旧比例，结果人和箱子一样高（甲）。
  发现是比例问题，就把三个目标放在同一张图上重新量、一起调
- **三个概念图人物共用同一套肤色** —— `SKIN = 0xb7c1c7` / `SKIN_SHADE = 0x8a949b`，
  于是「浅色块 = 人」成了玩家不用学的规则（三张概念图本身也都是没有五官的浅色头，
  这是美术方向，不是占位）。按概念图量出的人物高宽比：老周 1.67、陈老板 1.74、
  李副局长 3.00 —— 比例照量出来的数字分，不要凭感觉
- **量暖色剪影不要用亮度阈值** —— 对峙高光的琥珀色（`0xc9a227`，g/b≈4.2）
  连同它抗锯齿后的暗边会被一起算进去，量出来比人物实际高度大 40%。
  外套三色的 g/b 都在 1.44~1.50，用 `r>=55 && r>g>b && g/b<1.75` 才量得准
- **竖屏底部留 28px 安全区** —— 真机的手势条与圆角会盖住最下面一条。
  道具栏因此按行数给格子高度（1 行 68、2 行 58）再往上排，
  而不是固定 68 从顶往下堆：那样一行止于 1208、两行顶到 1274，同一个控件两套位置
- **版面槽位固定、让字号去适应内容，不许反过来** —— 结局屏正文排在固定槽位
  246..772、插画固定 796..1046，排不下就把字号从 20 降到 14。
  原来插画位置跟着文案长度走，文案一长插画就被整块跳过，下半屏一片空白
- **「当前交互对象」必须有只作用于它的状态** —— 对峙场三个目标原来是同一套
  「圆顶压柱体」，两屏之间场景像素完全相同，玩家不知道自己在跟谁说话。
  现在描边 + 地面光 + ▼ 三者叠加，且人和货箱的剪影明确分化
- **结局色调靠色相分道，不靠明度差** —— 只用明度区分时相邻两屏底色只差 3~10 个
  RGB，最坏的结局反而是最暗最干净的那一屏。改成六个色相 + 0.3 的叠加强度
- **悬挂标点要在行末溢出，不能另起一行** —— `ui/cjkWrap.ts` 里遇到
  `，。、；：？！` 这类避头标点时把它并进当前行，而不是关行让它独占下一行的行首
- **动效只动 transform / alpha，不重画图形** —— 场景静态图有 900 多条图元，
  每帧重建 60 次是不可接受的。雨靠"周期位移"、灯和水光靠 alpha 呼吸、
  尘埃和雾靠两个错相的长 tween，全部是建层时画一次（见 10.7）
- **加一层动效 = 去静态图里删掉对应的那一笔** —— 走廊的三盏灯在底图里画过
  `glow()`，仓库外有 170 根静态雨线，动效层再叠一层就是双份亮度、
  或者一场雨下两遍。两套并存比不做还糟
- **Graphics 不裁剪** —— 它的绘制范围就是"你给的坐标"，没有"矩形之外不画"这回事。
  靠位移做循环的图层会把内容推出去整整一个周期（雨区设 0~600、雨丝画到 y≈1260）。
  要么用自带裁剪的对象（`TileSprite`），要么把坐标算对
- **Phaser 4 的 WebGL 下 `createGeometryMask()` 没有实现** —— 调用会报
  *"This method is not supported in WebGL. Create a Mask filter instead."*；
  而 Mask filter 的 `internal` 是"跟着被过滤对象一起动"、`external` 是"匹配相机"，
  两者都不是"钉死在屏幕上的矩形"，别指望用它当裁剪框
- **同一个属性挂两个 tween，后一个覆盖前一个** —— 想让尘埃沿一条不回环的轨迹飘，
  必须 x、y 各挂一个（且周期取互质），挂在同一个属性上只会变成一个方向的来回蹭
- **随机抖动要写成固定序列** —— `Math.random()` 让同一盏灯每次进来抖得不一样，
  截图对比时每张都不同，视觉回归就没法比。`addLamps` 的 `flicker` 走一张写死的表
- **渐变要按色差给段数，不是按"分几档"** —— 天空分 7 段（每段 88px）在屏幕上是
  七条硬边横带。暗场色域窄，每段给到 5px 上下才连成一片
- **动效层不许挡住回归** —— `settle` 步问的是 `__anJiao.idle()` 那六个游戏状态位，
  **不看 tween**。任何无限循环的动效都不能让 `idle()` 变 false，否则每条路线都会超时

### 11.4 调试钩子（只在 `?dev=1` 时挂载）

`window.__anJiao` 提供 `active() / pointer() / items() / names() / flags() /
keyCount() / clueCount() / give(...ids) / goto(sceneId) / restart() /
itemCell(id) / held() / hotspot(id) / scene() / padKeys() / idle() / neutral()`。
自动化脚本靠它跳过打字机动画、按**名字**定位道具栏格子与场景热点、在场景间跳转。
**生产构建里不带 `?dev=1` 就完全不生效**，不会泄漏到正式流程。

标题页另有两个口子：`titleButton(文字)` 取按钮中心（§9.8 的铜徽也登记成
`硬币` 这个名字，✕ 登记成 `关闭制作信息`，所以脚本点它们同样不用写坐标），
`titleCredits()` 返回制作信息面板开着没有 —— **不在标题页返回 `null`、
在标题页但关着返回 `false`**。把「不在这屏」和「在这屏但关着」合成一个 `false`，
断言就会恒真（C1 的证据列表踩过这个形状的坑）。

`hotspot(id)` / `neutral()` / `idle()` 是 P2 补上的：脚本一旦要写死坐标，
就会在布局改动后悄悄点在空气上，而报告仍然是绿的。
`neutral()` 由场景自己算出一块不落在任何热点上的空地 ——
第一章好用的 `(360,950)`，在第二章船长室正好压在办公桌上。

第 2 组又加了两个「把某个画面直接调出来」的口子，都是给美术验收用的：

- `plate(id)` —— 打开结局屏并**强制**用某个结局（内部走 `EndingScene` 的
  `preview: true` + `forceEnding`），用来逐张拍六张插画。六个 id 就是
  `data/endings.ts` 里的 `EndingId`，写错会被 tsc 拦下。
- `chapterCard(index)` —— 把第 index 张章节卡直接调出来。过场卡本身只停 1.7 秒，
  靠点击去凑它必然拍虚。

两个都遵守同一条口径：**不在对应的屏幕上返回 `null`、在但没开返回 `false`**。

### 11.5 烟测（`tools/smoke.mjs`）

零依赖 CDP 客户端（Node 24 内置全局 `WebSocket`），驱动 Edge `--headless=new`。
步骤 DSL：`wait:<ms>` / `click:<x>,<y>` / `click-item:<id>` / `hold-item:<id>` /
`drop-item` / `click-spot:<热点id>` / `click-confront:<目标id>` / `click-title:<文字>` /
`tap-center` / `code:<四位数字>` / `pad:<按键文字>` / `settle[:最大点击数]` /
`move:<x>,<y>` / `shot:<path>` / `eval:<expr>` / `assert:<表达式>` /
`expect:<表达式>` / `screen:<场景key>` / `evidence` / `evidence-close` /
`reread:<道具id>` / `back` / `back-confirm`。

运行参数：`--width` / `--height`（窗口尺寸）、`--input mouse|touch`、
`--steps-file <json>`、`--report <path>`。

十一条必须遵守的经验：

- **一律用 `click-item:<id>` / `hold-item:<id>` / `click-spot:<id>` /
  `click-confront:<id>` / `click-title:<文字>`，不要写死坐标** —— 写死坐标的脚本会在布局一变就集体失效，
  而报错方式是「点了没反应」，极难查。`hold-item` 是幂等的（已手持就跳过），
  因为再点一次是取消选中；探索场景与对峙场景各开了一个同名的道具栏查询口，
  DSL 因此不必知道自己在哪一幕里。
- **验收路线必须在手机尺寸 + 触摸下也跑通，不能只在 720×1280 上绿** ——
  `Scale.FIT` 会把 720×1280 的舞台缩放居中，**只有在正好 720×1280 的窗口里
  游戏坐标才等于页面坐标**。所以一条写死坐标的脚本在桌面上"通过"，
  换到 390×844 就会把每一次点击都派发到画布外面：脚本静默点空，
  只有 `hold-item` 之类会报错的步骤才显红。
  P5 收尾时就抓到 `p1.json` / `p1-hint.json` / `p2.json` 三条路线有这个问题
  （前两条各有 21 / 5 处写死坐标，`p1.json` 在手机上 61 步只报 3 个错，
  其余全在空转）。现在 `src/dev.ts` 的 `toPage()` 统一把游戏坐标换算成页面坐标，
  所有"给脚本点"的口子（`itemCell` / `hotspot` / `padKeys` / `neutral` /
  `confront().targets` / `titleButton` / `center`）都过这一道。
- **推进对话用 `settle`，不要数「点 N 下」** ——
  它一直点到场景报告"安静"为止（对话收起、章节卡落下、文档合上；
  在对峙里则等到「台词播完且轮到你出牌」；已经落到结局屏也算终点）。
  台词行数一改，固定次数就会少点或多点，之后的每一步跟着偏，而报告看起来仍然是绿的。
- **断言之前先 `settle`：剧情效果是顺序执行的** ——
  `say` 会一直 `await` 到玩家把话看完，排在它后面的 `flag` / `give` 在对话框收起前
  根本不会跑。点完热点立刻 `assert` `flags()` / `items()`，看到的是"什么都没发生"。
  P4 曾因此误判「音效没接上」，实际是台词还没说完。
- **判定结果要读出来，不要靠截图看** —— `EndingScene` 开了 `devEnding()`，
  脚本用 `eval:__anJiao.ending()` 直接拿到结局 id / 是否降级 / 破绽数。
  结局文案画在 canvas 上，DOM 里读不到，只看截图无法断言判对了没有。
- **能断言的就别只截图** —— 用 `assert:<表达式>` / `expect:<表达式>` 让脚本自己判真假；
  没有它，结局判错了、图鉴没写进存档，脚本照样一路绿，只能靠人翻截图发现。
- **JSON 报告必须用 `--report <path>` 写出，不能用 PowerShell 的 `>` 重定向** ——
  Windows PowerShell 5.1 的 `>` 会写成带 BOM 的 UTF-16LE，`JSON.parse` 直接失败。
  同理，读报告也别用 `Get-Content -Raw | ConvertFrom-Json`（它会按 ANSI 解码 UTF-8），
  要用 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`，且 **.NET 的相对路径
  按进程工作目录解析、不跟随 PowerShell 的 `cd`**，一定要拼绝对路径。
- **dev 钩子要靠 URL 里的 `?dev=1` 才会挂上** —— 为了绕缓存顺手写成
  `http://localhost:5199/?t=<时间戳>` 会把 `dev=1` 顶掉，于是 90 步里 47 步失败在
  `ReferenceError: __anJiao is not defined` / `拿不到画布中心` /
  `标题页没有按钮「开始调查」`。正确写法是 `?dev=1&t=<时间戳>`。
  这一条骗人的地方在于：报错看起来像"游戏坏了"，其实是脚本没进开发模式。
- **步骤文件参数是 `--steps-file`，不是 `--steps`** —— 写错时工具不报错，
  把它当位置参数忽略掉：0 步、`"steps": []`、`"ok": true`、3 秒返回。
  报告是全绿的，而实际上一个步骤都没跑。
- **开发钩子必须让「没开」和「开了但是空的」可区分** —— 证据列表的钩子一度分成
  `devRows()`（没开返回 `null`）和 `devClose()`（永远有值），场景那边一句
  `?? {}` 把它们拼成一个对象，于是"点开了吗"和"关掉了吗"两个断言**恒真**：
  列表根本没打开，`evidence` 步骤照样报 `0 行` 通过。现在只留一个
  `devPanel()`，没开就是 `null`，没有第二种解释 —— 假绿最爱藏在这种
  "顺手兜个底"的地方。
- **「打开浮层的那一次点击」的抬手会打到浮层自己身上** —— `DocumentOverlay`
  的 `pointerUp()` 里「没拖动就关」，把打开它的那一次点击的抬手也算成了一次关闭：
  在证据列表里点「重读原件」，原件弹出来又被同一个手势的抬手当场关掉。
  这是竞态，**同一份代码在 720×1280 鼠标下一直全绿、换 390×844 触摸就必红** ——
  所以"绿了"只对跑过的那个尺寸和那种输入负责。
  修法是记住"这次打开之后见过 pointerdown 没有"（`armed`），没见过就把抬手吃掉但不关。
- **验收计划本身也要被验** —— `c-landscape` 在桌面尺寸下断言横屏提示可见，
  必然失败：`--width 720 --height 1280` 是竖屏，提示层本来就不该出现。
  一条路线"红了"先看它是不是在错的条件下跑的，再去看游戏。
  同理，`c-class` 在手机上红、桌面绿，第一反应不该是"手机有问题"，
  而是"同一个手势在两种输入下的时序不一样，代码里有个竞态"。
- **一次跑完所有路线：`node tools/regress.mjs [--mobile] [--only <路线>]`** ——
  逐条起 `smoke.mjs`、用 Node 解析报告、汇总步数与异常数，最后打印
  `ALL GREEN` 或以非 0 退出码表达失败。手机尺寸的路线用 `<名字>@<宽>x<高>` 表示，
  条目里带 `width` / `height` / `input`。**不要再用 PowerShell 拼一遍循环** ——
  按 ANSI 解码 UTF-8 的报告会中文乱码，看起来像所有路线都失败。

另外记三条：

- **点空白处 = 放下手里的道具**，所以脚本里每次需要用撬棍之前都要重新 `hold-item:crowbar`。
- **成功使用道具不会把它放下** —— 撬棍用过之后还在手上，而"不带 `needs` 的分支"
  要求空手，于是「用完撬棍去点一个不需要道具的热点」会静默没反应
  （底舱返回口 `back_out` 就这么被卡住过）。依赖空手的点击之前先 `drop-item`。
- **进场景后先 `settle` 再点热点**：`onEnter` 台词是异步开始的，
  脚本若抢在它弹出之前点，第一下会生效、之后全被刚弹出的对话框吃掉。

### 11.7 仓库卫生（第 4 组 D2）

改动前：**没有 `.gitignore`**，`node_modules`（4415 个文件）和 `dist` 被提交进了库，
`.git` 涨到 49.56 MB；提交信息只有 `try` / `try` / `try` / `1` / `杂项`；
`docs/README.md` 是 0 字节；`shots/` 根目录散着 122 个文件。

改动后跟踪文件 **4672 → 97**：

| 项 | 处理 |
|---|---|
| `node_modules/` `dist/` | `git rm -r --cached`（磁盘文件一个没动），写进 `.gitignore` |
| `shots/` 根目录 122 个文件 | 52 个按路线归位到 `shots/<路线名>/`；15 个旧报告删除；56 个老图挪进 `shots/_legacy/` |
| `shots/_regress/` 24 个机器报告 | 一并请出索引（`regress.mjs` 随时能再生） |
| `docs/README.md`（0 字节） | 删除 |
| 根 `README.md` | 新增（怎么跑、怎么回归、素材与 AI 使用） |

`.gitignore` 就三条：

```
node_modules/        # 一条 npm install 就能再生
dist/                # 一条 npm run build 就能再生
shots/               # 每次回归重拍上百张图，97 张里 68 张会变
```

**为什么连 `shots/` 都不跟踪**：雨、尘埃、灯光呼吸都有相位，回归每跑一次就有
一大半截图变样（4.44 MB 里约 3 MB）。跟踪它等于每次回归都往历史里塞 3 MB
二进制 —— 跟当初把 `node_modules` 提交上去是同一类错误。
给人看的图另挑了一份**静态的**放在 `docs/截图/`（9 张，只在美术真改了时手动更新）。

**`tools/steps/*.json` 里的 `shot:` 路径与 `shots/` 的目录结构是一对**：
路线截图写到 `shots/<步骤文件名去掉扩展名>/`，改目录必须同步改步骤文件，
否则下一次回归会把图又写回根目录。`_` 开头的路线（`_motion` / `_plates` /
`_gallery` / `_chapter` / `_debug-open` …）按需跑、不进回归矩阵、产物不进库。

**还没做的**：`.git` 仍是 53 MB —— 历史里的 `node_modules` 是 215.95 MB 未压缩对象
（用 `git rev-list --objects --all | git cat-file --batch-check` 量的）。
这些对象挂在旧提交上，`.gitignore` 管不到它们，只有重写历史才能回收：

```bash
pip install git-filter-repo
git filter-repo --path node_modules --path dist --invert-paths
```

代价是**所有提交的 SHA 都会变**，而 `origin/main`（gitee）上已经有这些提交，
必须 force push。对一个人的比赛仓库可以接受；有别人在同一个仓库上工作时不要做。
